Project Structure
=================

To ensure compatibility with MODIS, we recommend structuring your project as described below. This approach will also help you keep your code, data, and experiments organized and maintainable.

.. code-block:: text

    project_name/
    ├── config/                                        # Configuration files
    │   └── config.yaml
    ├── data/                                          # Data directory
    │   └── toy_dataset/                               # Dataset name
    |       └── dna_methylation_unpaired_x_train.csv
    |       └── dna_methylation_unpaired_y_train.csv
    ├── src/                                           # Source code directory
    │   └── generate_dataset.py
    ├── notebooks/                                     # Jupyter notebooks (optional)
    │   └── results_exploration.ipynb
    └── results/                                       # MODIS output (autogenerated)


Directory Descriptions
----------------------

**config/**
    Contains configuration files that define the parameters for a experiment or training run.
    Keeping configurations separate ensures that experiments are reproducible, easy to modify, and well-documented.
    For more details, refer to the :doc:configuration section.

**data/**
    Stores all datasets used in your project. Each dataset should be organized within its own subfolder (e.g., ``toy_dataset/``).  
    Following this structured layout, which simplifies data loading and experiment management.  
    Example files include feature matrices (``*_x_train.csv``) and corresponding labels (``*_y_train.csv``).

**src/**
    This directory is intended for storing the scripts used in data preprocessing.
    Here, you can define a function that generates a PyTorch dataset class, which will later be passed to MODIS, as explained in a subsequent section.

**notebooks/**
    Optional directory for Jupyter notebooks used for exploratory data analysis, visualization, or results inspection.  
    This folder is ideal for interactive experimentation or sharing insights about model performance.

**results/**
    This directory is automatically generated by MODIS and stores all experiment outputs, including model checkpoints and logs.
