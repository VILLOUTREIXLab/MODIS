Training (modis.training)¶

This section documents the training orchestration layer: the Trainer class, the epoch-based training loop functions, and the loss functions used during training.

Top-Level Functions¶

These functions are importable directly from modis:

train(config, train_datasets, val_datasets=None, show_dataset_summary=True, run_evaluation=True, generate_plots=True, checkpoint_path=None, read_args=True)[source]¶

Orchestrate the complete MODIS training workflow.

Calls train_loop() and optionally runs checkpoint evaluation and diagnostic plot generation afterwards.

Parameters:

  • config (omegaconf.DictConfig) – Training configuration object.

  • train_datasets (list[torch.utils.data.Dataset]) – Training datasets, one per modality.

  • val_datasets (list[torch.utils.data.Dataset], optional) – Validation datasets, one per modality. Defaults to None.

  • show_dataset_summary (bool) – If True, prints dataset summaries before training. Defaults to True.

  • run_evaluation (bool) – If True, evaluates saved checkpoints on both training and validation datasets after training. Defaults to True.

  • generate_plots (bool) – If True, generates and saves diagnostic plots for each saved checkpoint. Defaults to True.

  • checkpoint_path (Path | None) – pathlib.Path path object to the checkpoint to be resumed or None.

  • read_args (bool) – If True, parses CLI arguments inside train_loop(). Defaults to True.

Returns:

Path to the checkpoint directory, or None if the training loop did not produce any checkpoints.

Return type:

pathlib.Path or None

train_loop(config, train_datasets, val_datasets=None, show_dataset_summary=True, checkpoint_path=None, read_args=True)[source]¶

Execute the core epoch-based training loop.

Iterates over the training data for the configured number of epochs, performs training steps via Trainer, logs metrics, and saves checkpoints.

If read_args=True and a --checkpoint argument is supplied on the command line, training resumes from that checkpoint.

Parameters:

  • config (omegaconf.DictConfig) – Training configuration object.

  • train_datasets (list[torch.utils.data.Dataset]) – Training datasets, one per modality.

  • val_datasets (list[torch.utils.data.Dataset], optional) – Validation datasets, one per modality. When provided, validation accuracy is computed each epoch and factored into the best-checkpoint criterion. Defaults to None.

  • show_dataset_summary (bool) – If True, prints a dataset summary table before training begins. Defaults to True.

  • checkpoint_path (Path | None) – pathlib.Path path object to the checkpoint to be resumed or None.

  • read_args (bool) – If True, parses command-line arguments to check for a checkpoint path. Set to False when calling programmatically to avoid conflicts with sys.argv. Defaults to True.

Returns:

Path to the checkpoint directory if at least one checkpoint was saved; None otherwise.

Return type:

pathlib.Path or None

Trainer¶

Trainer for the MODIS multi-modal model.

This module contains the Trainer class, which orchestrates the training process. It manages the optimization loops, calculates various loss functions, and handles model checkpointing.

The Trainer class is responsible for:

  • Initializing the model, optimizers, and loss functions.

  • Implementing the training loop for both the VAEs (generators) and the Discriminator.

  • Calculating and backpropagating reconstruction, KL divergence, adversarial (relativistic), auxiliary, and clustering losses.

  • Saving and loading model and optimizer states for checkpointing.

  • Performing a single training step.

train_step(x, y, is_labeled)[source]¶

Perform a single training step for both the VAEs and the Discriminator.

The step consists of two sequential phases:

  1. Discriminator phase — the VAEs are frozen and the discriminator is updated using adversarial, auxiliary, and clustering losses.

  2. Generator phase — the discriminator is frozen and the VAEs are updated using reconstruction, KL divergence, and discriminator feedback losses.

Parameters:

  • x (list[torch.Tensor]) – Per-modality input tensors, each of shape (batch_size, n_features).

  • y (list[torch.Tensor]) – Per-modality label tensors of shape (batch_size,). Unlabeled samples should carry label -1.

  • is_labeled (list[torch.Tensor]) – Per-modality boolean tensors indicating which samples are labeled (True) or not (False).

Returns:

A dictionary of scalar training metrics for this step:

  • d_train_loss (float): Total discriminator training loss.

  • recon_loss (float): Reconstruction loss across all modalities.

  • kl_loss (float): KL divergence loss across all modalities.

  • d_loss (float): Discriminator feedback loss used in the generator update.

  • d_cluster_loss (float): Clustering loss component.

  • d_aux_acc (float or None): Auxiliary classifier accuracy on labeled samples (None if no labeled samples are present).

  • d_adv_acc (float): Adversarial (modality) classifier accuracy.

  • g_loss (float): Total generator loss.

  • r (list[float]): Per-modality gradient penalty values (empty list when relativistic loss is disabled).

  • modal_recon_loss (list[float]): Per-modality reconstruction losses.

  • modal_kl_loss (list[float]): Per-modality KL divergence losses.

Return type:

dict

Loss Functions (modis.training.losses)¶

Loss functions for training MODIS.

This module provides clustering and regularization loss functions used during training, including a Deep Divergence-Based Clustering (DDC) loss and an entropy regularization loss.

The key components are:

  • DDCLoss: Implements the DDC loss, which encourages compact and separable clusters in the latent space.

  • EntropyLoss: A regularization loss that prevents the model from collapsing all samples into a single cluster.

  • ClusteringLoss: A combined loss summing the DDC and entropy regularization terms.
